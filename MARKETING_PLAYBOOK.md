# GitHub Portfolio Marketing Playbook

**Owner:** elon00 · **Date:** 2026-11-13 · **Purpose:** Organic developer/community marketing with evidence-first claims.

## Positioning

Primary headline: **Martin Luther — AI Agents, Blockchain Infrastructure & Post-Quantum Security**.

Audience: open-source contributors, protocol teams, security researchers, hackathon organizers, potential technology partners, and recruiters. Lead with a specific capability and link to genuine artifacts.

## Conversion path

1. A visitor encounters the concise profile headline.
2. The profile README directs the visitor to a relevant flagship repository.
3. Each flagship README demonstrates: problem, solution, architecture, quickstart, tests, verified deployment status, limitations, and contribution/contact route.
4. Interested visitors submit an issue, discussion, or partnership inquiry through an owner-approved channel.

## Per-flagship quality gate

- [ ] Clear value proposition and target user
- [ ] One command to run local demo (if feasible)
- [ ] Real screenshots, architecture diagram or reproducible demo
- [ ] Source license and contribution policy
- [ ] CI and test instructions with actual results
- [ ] Security and threat model disclosure
- [ ] Explicit status: concept / prototype / tested / testnet verified / mainnet verified
- [ ] Exact explorer links and tx evidence if on-chain claims are made
- [ ] No fabricated metrics, endorsements, certifications or promised returns
- [ ] Open issues and a contributor-friendly first task

## 30-day organic marketing cadence

**Week 1:** Finalize profile; select six flagship repos; repair descriptions, topic tags and README entry points.

**Week 2:** Publish two technical explainers: QARBI architecture and shor-x402 payment proof / negative testing. Include links to specific commits and runnable examples.

**Week 3:** Publish short developer demos, contribute to relevant open-source discussions, and create beginner-friendly issues. Ask for technical feedback, not artificial star/follower exchanges.

**Week 4:** Publish an evidence-backed monthly changelog. Compare traffic, stars, clones, unique contributors, issues and meaningful collaboration inquiries against a recorded baseline.

## Monthly scorecard (do not pre-award)

| --- | --- |

| Documentation engagement | Visits to demos/docs and completed onboarding |
| Community growth | External contributions and substantive issues/PRs |
| Partnership pipeline | Relevant inquiries, accepted calls and joint deliverables |

| Reputation hygiene | Unsupported claims removed and outdated links fixed |

Record baseline and exact observation dates; distinguish missing data from zero.

## Distribution channels

Use GitHub Discussions, README cross-links, technically relevant LinkedIn posts, developer communities, research notes, and hackathon submissions. Tailor messages to each community's rules. Do not use bots for mass unsolicited outreach, paid/artificial stars, misleading badges, or engagement manipulation.

## Editorial rule

Use **"exploring," "building," "testing,"** or **"verified on [network] at [transaction]"** precisely. Never replace these with blanket `production-ready`, `NIST certified` or `100/100` claims without independent evidence.
